# 영상 단위 재평가

최종보고서의 "정밀도 1.00 / 재현율 0.75"를 더 엄격한 절차로 재측정.

## 1. 요약

| 판정 규칙 | 재현율 (치트 25개) | 오탐률 (정상 230개) |
|---|---|---|
| 기존 설계: 윈도우 하나라도 임계값 초과 | 0.59 (11~21개) | 0.61% (0~3개) |
| 개선안: 영상 평균 확률 | 0.76 (16~21개) | 0.26% (0~2개) |
| 참고: 영상 평균 확률 > 0.5 | 0.87 (20~23개) | 0.96% (1~5개) |

- 값은 10회 반복 평균, 괄호는 반복별 최소~최대.
- 영상 단위 ROC-AUC 0.994~0.997.

## 2. 재평가 배경

기존 노트북: `01_training_xgboost_model_precision_threshold.ipynb`

- 영상 단위 분할 적용. 윈도우 누수 없음.
- 임계값(0.9989)을 검증셋에서 "오탐 0이 되는 지점"으로 선택 후 같은 검증셋으로 성능 보고.
- 분할 1회(시드 42). 검증셋 치트 영상 약 8개.
- 재현율 0.75는 윈도우 단위(0.20)가 아닌 영상 단위 후처리 결과.

## 3. 방법

| 항목 | 내용 |
|---|---|
| 데이터 | `preprocessed_data.xlsx`. 윈도우 5,569개, 영상 255개 |
| 분할 | `StratifiedGroupKFold` 5-fold × 10회 반복 |
| 임계값 | 학습 폴드 내부 4-fold의 out-of-fold 예측에서만 결정 |
| 하이퍼파라미터 | 기존 노트북 탐색 결과 고정 |
| 지표 | 영상 단위(실제 제재 단위) 집계 |

데이터 출처: [Anti-Cheat-Model](https://github.com/Chunsaeng20/Anti-Cheat-Model)의 `dataset/`

## 4. 해석

### 4.1 보고서 수치의 성격

- 보고서 표는 기존 분할에서 실제로 나온 값. 재현 가능.
- 임계값을 검증셋에 맞춘 뒤 같은 검증셋으로 측정. 새 데이터 기대 성능보다 높음.

### 4.2 기존 설계

- 임계값을 학습 데이터에서만 정하면 재현율 0.59로 하락.
- 오탐 0 유지 안 됨.
- 원인: 윈도우 하나에 의존하는 규칙이 정상 유저의 순간 플릭에 취약.

### 4.3 개선안

- 영상 평균 확률로 판정 시 재현율 0.76, 오탐률 0.26%.
- 95% 신뢰구간: 재현율 0.59~0.93, 오탐률 0~1.6%.
- 치터 비율 1% 가정 시 정밀도 약 75%.
- 용도: 자동 제재가 아닌 신고 건 우선순위 정렬.

## 5. 홀드아웃 검증

학습과 임계값 결정에 한 번도 쓰이지 않은 영상 91개(치트 43, 정상 48)로 최종 검증.

### 5.1 홀드아웃 영상의 출처

- Storage 전체 347개 중 기존 데이터셋에 쓰인 것은 256개. 나머지 91개가 홀드아웃.
- 38개: 기존 전처리 엑셀 생성(2025-10-12) 이후 업로드. 대부분 2025-10-31 치트 영상.
- 53개: FPS 메타데이터가 1000으로 기록된 영상. 기존 전처리의 "시작 3초 스킵"이 3000프레임을 건너뛰어 분석 실패 처리되던 것. FPS를 30으로 간주해 복구.

### 5.2 절차

1. 임계값: 기존 255개 영상의 5-fold OOF 예측에서만 결정.
2. 모델: 기존 255개 전체로 학습.
3. 홀드아웃에 1회 적용. 절차는 결과 확인 전에 고정.

### 5.3 결과

| 판정 규칙 | 재현율 (치트 43개) | 오탐 (정상 48개) |
|---|---|---|
| 기존 설계 | 0.58 (25개) | 0개 |
| 개선안 | 0.79 (34개) | 4개 (8.3%) |
| 참고: 영상 평균 확률 > 0.5 | 0.98 (42개) | 4개 (8.3%) |

- 재현율: 교차검증 추정치와 일치. 기존 설계 0.59 → 0.58, 개선안 0.76 → 0.79.
- 오탐률: 개선안은 교차검증(0.26%)보다 크게 높음. 95% 신뢰구간 2.3~20%.
- 기존 설계는 홀드아웃에서 오탐 0. 개선안의 "오탐 감소"는 홀드아웃에서 재현되지 않음.
- 기존 방식으로 처리된 38개만 보면 개선안 23/31, 오탐 1/7.

### 5.4 오탐 4건 분석

- 3건: 거의 움직이지 않은 영상. 평균 속도 0.2~0.6 (정상 중앙값 2.8), 정지 프레임 20~30%, 최종 점수 0~1점.
- 1건: 일반적인 플레이 (평균 속도 1.3, 최종 점수 5점).
- 기존 학습 데이터에서는 평균 속도 하나만으로 ROC-AUC 0.90. 치트 영상이 덜 움직인다는 점을 모델이 일부 학습.
- 결론: 플레이를 거의 하지 않은 영상을 치트로 판정하는 약점 확인. 활동량이 기준 미만인 영상은 판정 보류하는 단계 필요.

## 6. 한계

1. 표본 부족. 치트 영상 68개, 홀드아웃 정상 영상 48개로 오탐률 신뢰구간 넓음.
2. 저활동 영상 오탐. 5.4 참고.
3. 녹화 환경 편향 가능성. 치트 영상은 데스크탑 1~2대(1920×1080), 정상 영상은 불특정 다수 브라우저(1280×720~3840×2160)에서 수집. 홀드아웃의 1920×1080 정상 영상 5개는 모두 정상 판정이나, 같은 데스크탑에서 핵 없이 플레이한 영상으로 확인 필요.
4. 특징 단위가 px/frame. 해상도와 프레임레이트에 따라 같은 동작도 다른 값.
5. 에임봇 1종, 설정 1종. 다른 종류의 핵에 대한 일반화 미검증.
6. FPS 보정 영상 53개는 실제 프레임레이트를 30으로 가정.

## 7. 실행

```
pip install -r requirements.txt
python reeval.py preprocessed_data.xlsx reeval_summary.json
python plot_reeval.py
python extract_aim.py <영상 폴더> holdout_aim.csv
python holdout_eval.py preprocessed_data.xlsx holdout_aim.csv holdout_summary.json
```

- `extract_aim.py`: 영상에서 프레임별 에임 특징 추출. 기존 엑셀과 프레임 단위로 일치하는 것 확인. 영상 원본은 저장소에 미포함.
- `holdout_eval.py`: 홀드아웃 평가. 수치 요약(`holdout_summary.json`)과 영상별 판정(`holdout_summary_videos.csv`) 생성.

- `reeval.py`: 수치 요약(`reeval_summary.json`)과 영상별 판정 결과(`reeval_summary_videos.csv`) 생성.
- `plot_reeval.py`: `figures/`에 그림 2장 생성.
  - `summary.png`: 규칙별 재현율·오탐률. 점 1개 = 반복 1회.
  - `score_separation.png`: 규칙별 영상 점수 분포. 반복 1회분.
